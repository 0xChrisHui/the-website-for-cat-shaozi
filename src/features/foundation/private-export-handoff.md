## Call sites for the exports owner

- Request through `requestPrivateExport({ requestId })` in `private-export-access.ts`. It verifies same origin and a maintainer or signed private sample session. Preserve the request UUID across retries. A new request shares active work or starts one generation and retires the prior pointer. Keys for coalesced requests remain idempotent once the job finishes.
- In `exports/jobs.ts`, consume `context.privateExport` for `exports.private-zip`. Use `recheck()` for current authorized candidates and recheck before upload. Match the archive manifest against `claim.versions` and upload only to `claim.objectKey`, without overwrites. Pass the supplied abort signal to storage, await upload settlement, and call `publish()` only after confirming the private object and its size. Leave every failed or ambiguous upload/publication for the worker's cleanup loop. Throw if storage may still complete asynchronously, so the worker keeps the reservation for later deletion checks. The worker still holds its existing session lock while the handler runs. The loop retires any unfinished reservation when the handler returns, and recovery handles abandoned work after restart.
- Sign with `withCurrentPrivateExport(async (pointer) => ...)`. Sign `mode: "private"` for private GET with a maximum 60-second lifetime and cache bypass, while the callback holds the scope transaction lock. Serve `mode: "mock"` from `mockBytes` as a no-store sample response. A missing or revoked pointer returns null.
- Call `generateSamplePrivateExport(generate)` from the authenticated, same-origin sample flow. The callback receives only authorized candidates for that signed run and a synthetic-media reader. Return the small ZIP buffer. Mock bytes and publication commit together, with an 8 MiB ceiling. Sample invalidation removes Mock bytes in the same database transaction. Newly initialized sample fixtures include a private-only photo and an exportable diary after approval.
- Wrap future changes to current revisions, export-purpose authorizations, exclusion or in-place exported content in `withExportMutation(db, scope, mutate)`. Its callback reports whether the change affects exports. The wrapper locks the scope before taking item locks and invalidates within the same transaction. Use the same derived scope as the review transaction. The base has withdrawal and approval writers, both wired here. Intake inserts initial versions for new unapproved items, and review sample setup inserts fresh unapproved items with initial rights, versions and exclusion. Direct SQL writers would need to participate in this boundary.

Apply the foundation-owned additive migration before running updated web and worker code. It adds the reservation and cleanup ledger, one-active-job and one-current-object constraints, sample job RLS and grants to the existing web and worker roles. The real pointer lives in `current_export`. Cleanup backs off per object. An interrupted upload keeps a durable record and is checked periodically because a storage write can finish after its worker loses the connection. No extra role or PostgreSQL function/trigger is required. The migration and worker operate on the configured environment's existing business schema. The feature owner still needs to connect the generator, maintenance UI and download route, and verify actual Blob deletion and signed-link expiry in the authorized test environment.

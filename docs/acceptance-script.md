# 项目一 · 预览验收

打开测试 Preview。标明现场阶段的真实素材或外部服务验证只在对应阶段做，平常用预览里的样本操作。

E2 首个 `integration` Preview 成功后，先核对部署项目、分支和 SHA，再将固定默认别名填入 `TEST_CALLBACK_ORIGIN`。E3 用它验证实际投递。

| 板块 | 操作 | 预期 |
| --- | --- | --- |
| 地基 `foundation` | 打开预览首页，再用测试维护者登录进入「任务诊断」。E3 用手机投三张授权原图，含 HEIC 和一张超过 4.5 MB 的照片；重投同一批。 | 匿名打不开任务诊断；登录后看得到编号。真实原图持久化后刷新仍在，重投只有一条任务。损坏一件附件时按编号能查到短原因。 |
| 投稿 `intake` | 点「维护后台 → 样本登录 → 投稿待办 → 投递样本」，再点「重投同一事件」。打开这条草稿，设置其中一张照片的日期。联调时再用同样的真实大小文件上传并原样重投一次。 | 只出现一条草稿，条目不重复，逐图日期覆盖共同日期，冲突显示「日期待确认」。大图可以直传，HEIC 原件保留。 |
| 纪念站 `memorial` | 从「审核投稿」批准一张照片并发布。用隐身窗口打开首页和「时间线」，随后在后台撤下它，再刷新并访问旧媒体地址。另核对一张标为不上链的私有照片。 | 已批准的当前版本可见；撤下后页面和旧媒体入口均不可访问。不公开的私有照片始终不出现在公开页面。 |
| 永久归档 `permanent` | 用测试样本在后台批准一张获准归档和铸造的照片。先保持执行开关关闭，再在测试网或沙箱启用对应开关，重复提交同一个操作。 | 关闭时无外部写入；启用后先确认归档再出现到账记录。同一照片只有一份归档和一条铸造记录，失败或结果未知时有任务编号和短原因。 |
| 离线快照 `exports` | 在维护后台点「生成离线快照」和「下载离线快照」，断网解压查看。再生成一次，撤下包里一张图后，重查站内下载和旧链接。 | 离线能读图文；服务器只保留一份当前结果。撤下时立即关闭站内下载，旧对象删完后旧链接失败。重生成的新包不含撤下素材。 |

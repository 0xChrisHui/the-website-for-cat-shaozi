# 永久归档模块需要地基决定

本轮在 `fix/permanent-1` 上核对了基线 `a9ad0f0fe5f391b2e9da590b8025cd81f8b198de`，对应计划 `389e2c9562952ec7fe83898fc9fb6de27b350f98`。本轮初始化已通过。

## 需要地基变更

- **自动入队和恢复。** `src/lib/contracts/jobs.ts` 的 `WorkerContext` 只提供文件读取、结束任务和时钟。`src/features/foundation/worker.ts` 只在取出已排队任务后调用模块，重启时将运行中的永久任务转为人工核对。现有迁移也未授予工作器在 `jobs` 上插入的权限。计划 3.1 要求空队列时也能核对受信发布证据并按部署键自动入队，以及重启后按原凭证继续核对。
- **广播前持久化与授权。** `operation_receipts` 已有工作器专用读写权限，但工作器插座未提供按操作键锁定和持久化凭证的接口，也未提供读取当前批准版本、撤下状态、接收配置及在途费用的操作。地基应明确可由现有表和最小权限支撑的事务边界，并提供维护后台可读取的受限凭证。
- **适配器和受信输入。** 共享沙箱仅提供归档数据标识与链 ID 查询。计划 3.1–3.3 还需要受信发布记录来源、与发布绑定的构造配置、签名与回执核对接口，以及与审批绑定的日记修订和口令来源。

请维护者授权单独的地基修复，确认上述契约和最小权限。若需要调整数据库结构或权限，先按 `.ai/prompts/must-human.md` 决定。地基接口交付后，在固定基线重跑本模块，依次核对先存后发、超时后按原凭证恢复、撤下后拦截和 Mock 重跑幂等性，再开启永久模块验收。生产执行闸保持关闭。

当前只记录阻塞，保留模块验收开关为关闭。`stage0/github/protected-paths.txt` 在本工作树中不存在，本轮采用计划指定的 `.github/protected-paths.txt` 核对范围。

## 决定记录

- **决定。** 本轮不做任何可逆的测试性选择，不改代码、迁移、权限或验收开关，`e2e/acceptance/delivered/permanent.json` 保持 `{"delivered": false}`，转交维护者（must_human）。
- **理由。** 缺口是共享契约和数据库权限：`WorkerContext`（`src/lib/contracts/jobs.ts`）无入队、凭证锁定持久化接口；迁移 `jobs` 上工作器角色仅有 `select` 和 `update (status, reason, updated_at)`，无 `insert`。按 `.ai/prompts/must-human.md`，缺共享契约、改数据库结构或权限属"做不了"，须搁置。本板块可写路径也不含 `src/lib/contracts/**` 和地基迁移。用 Mock 在板块内绕开会让「先存后发」「重启按原凭证恢复」无法在真实工作器路径上验证，属降低验收强度。
- **备选。** ① 在 `src/features/permanent/**` 内自带入队和凭证表：越出可写路径，且需新增表，被否。② 用 Mock 假装工作器具备接口并翻开交付开关：会使验收通过而实际不可运行，被否。③ 仅交付合约 `contracts/src/**` 和纯函数部分（压缩、日记信封）：可行，但在地基接口未定前无法接线，由维护者决定是否先行拆分。
- **撤回。** 本轮没有代码改动，仅此文档；删除本文件即可撤回。地基修复合并后，在固定基线重跑本模块。

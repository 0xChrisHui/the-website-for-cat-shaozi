# 私有离线快照交付边界

基线 `8efeefec4d073fb7814b8f248a1ee067e5c04324` 已锁定 Archiver，并允许工作器读取审批、用途授权和版本。导出模块实现了当前批准版本的候选查询、共享政策复核、展示图与获准不上链原件的分流、离线归档以及发布与对象回收的工作器流程。上线开关仍关闭。

归档对原件校验批准版本的大小与 SHA-256。图像缩放至最长边 4096 像素并重编码为 WebP，去掉原图元数据，旋转按原图方向处理。清单哈希以最终归档成员为准。单张输入上限 100 MiB，累计媒体上限 512 MiB，文本上限 8 MiB，最多 500 项，生成写入私有临时目录。可见文字只取获准修订的日记与图注。

## 需要工作流决定的跨模块契约

- **撤回、权限、当前版本与排除。** `src/features/review/withdraw.ts` 的事务只更新 `items.withdrawn_at`。受保护的 `.github/scripts/migrate-schema.mjs` 禁止业务迁移创建触发器或函数。请授权相关写入方在同一事务调用共享失效操作，或由地基交付同等原子性的数据库机制。最小合同为按环境及样本范围序列化导出状态，更新素材时关闭已有指针、作废已排队及在途的生成令牌并持久记录待删对象。发布前在同一序列化边界再次检查令牌、候选版本与权限，再原子完成任务和指针。下载签发也在这条边界中读取当前指针。
- **持久化及工作器。** 使用 `jobs` 保存幂等请求键和活跃生成，真实环境使用 `current_export` 保存唯一当前指针。需要原子 claim、发布 CAS 和持久清理待办，支持撤回、失败、工作器重启以及发布响应丢失。未确认发布时禁止直接删除可能已成为当前结果的对象。复用工作器单实例锁，确保同一对象的在途上传结束后再确认删除。需要在无新导出任务时也执行清理，并把受环境限制的持久操作绑定到既有 `exports/jobs.ts` 插座。
- **样本隔离及审核。** 当前样本审批 fixture 私有导出默认为 false，明确不上链样本没有可校验的本地原件。请由审核提供明确授权的合成图文及撤回目标，并为每个样本 run 提供单独的状态和 Mock 存储绑定。现有工作器只领 `sample_run_id is null` 的任务，预览需要按经验证的样本会话处理小型 Mock ZIP。站内维护页和生成、下载路由等到契约就绪再接入，同源维护授权为入口，签发真实对象的 URL 使用不超过 60 秒的私有 get 权限并绕过缓存。
- **旧链接现场验证。** Blob SDK 的 `useCache: false` 为 URL 添加 `cache=0`，该参数不在签名内。D1 需在测试 Blob 确认删除后用原始未过期链接复读。工作器必须保留未确认清理记录。生成上传确认检查私有绕缓存可读、键名及大小。

锁定验收用例和交付开关保持原样。模块测试使用本地合成数据及 Python 标准库 ZIP 解包。它们覆盖离线打开、清单校验、权限选择与模拟撤回、上传错误和发布结果未知后的对象清理。数据库并发 claim、维护会话和撤回后真实短链失效仍需在完成上述契约后验收。

## 本板块已采取的可逆测试选择

| 决定 | 理由 | 备选 | 撤销方式 |
| --- | --- | --- | --- |
| 在无共享合同时，仅交付独立的 ZIP 生成与发布流程，对象存储、权限和撤回均用 Mock 与合成数据验证，交付开关保持 `false`。 | 问卷 Q33、Q34 和计划板块 4 要求撤回与生成同事务作废，该合同尚未存在；提前开启会放行未验证的下载入口。 | 先接入未经原子保护的下载路由。该路径会在撤回与生成竞态时重新开放旧结果，因此不采用。 | 合同就绪后接入持久化与路由，再把 `exports.json` 置为 `true`，无需删除现有代码。 |
| 展示图最长边 4096 像素、重编码为 WebP，单张 100 MiB、累计媒体 512 MiB、文本 8 MiB、最多 500 项。 | 满足计划所称去元数据与大尺寸原图的有界流式 ZIP；数值只影响测试和预览。 | 保留原始字节或不设上限。前者会带出元数据，后者无法保证有界。 | 调整 `archive.ts` 中的常量，并同步更新测试。D1 实测大 ZIP 后可再校准。 |
| 清单哈希以最终归档成员为准，可见文字只取获准修订的日记与图注。 | 离线解压后校验的是包内文件，原始字节哈希不能对应。 | 记录源文件哈希。它会与成员字节不一致。 | 改 `manifest` 生成并同步测试。 |

以上均不改变问卷或计划里的明确答案，也不涉及真实数据、账号或生产操作。

## 必须由维护者处理（`must_human`）

依据 `.ai/prompts/must-human.md` 第⑥项（改守卫）以及“改数据库结构或缺共享契约属于做不了，同样搁置”，以下事项不能由本板块代决：

1. **原子撤回合同缺失。** `src/features/review/withdraw.ts` 只更新 `items.withdrawn_at`，受保护的 `.github/scripts/migrate-schema.mjs` 禁止业务迁移创建触发器或函数。计划 2.2 与板块 4 要求在同一事务关闭当前指针并作废在途生成。
   - 请询问维护者：选择 (a) 授权 `review` 板块在撤回、权限和版本写入的同一事务中调用共享失效操作；或 (b) 由地基交付等价的数据库机制，同时放宽守卫对该机制的限制。两者不能由 `exports` 自行完成。
2. **共享数据库授权和结构。** 工作器对 `jobs`、`current_export` 的原子 claim、发布比较并交换和持久清理待办，需要新增字段或授权。这属于改数据库结构，首个项目含新增字段。
   - 请询问维护者：是否批准地基迁移补充这些列与授权，以及由谁执行。
3. **样本隔离输入。** 审核需提供明确授权私有导出的合成图文、撤回目标，以及按样本运行区分的状态与 Mock 存储绑定。现有 fixture 的私有导出为 false，明确不上链样本没有本地原件。
   - 请询问维护者：是否同意审核板块更新 fixture，还是改由地基统一提供。

在 1–2 解决前，维护页、生成与下载路由、并发 claim 验收和真实旧链接失效（D1）不会接入，`exports.json` 不改。草稿与测试保留在 `fix/exports-1` 工作树，Git 索引在本次运行中只读，尚未提交。
